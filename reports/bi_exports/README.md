# Power BI extracts

Generated by `python -m src.export_bi`. One CSV per star-schema table. The files are gitignored, so regenerate them after any change to the pipeline.

## Files

| File | Rows | Key | Role |
| --- | ---: | --- | --- |
| `fact_sales.csv` | 9,994 | `row_id` | Fact, one row per order line |
| `dim_customer.csv` | 793 | `customer_key` | Customer and segment |
| `dim_product.csv` | 1,894 | `product_key` | Category, sub-category, product |
| `dim_geography.csv` | 632 | `geography_key` | City, state, region |
| `dim_date.csv` | 1,464 | `date_key` | Calendar, mark as the date table |

## Import

In Power BI Desktop, Get Data > Text/CSV for each of the five files. The CSVs are UTF-8 with an ISO date format, so the default type detection is correct. Check that `postal_code` imports as a whole number and not text: 11 rows are blank, which can make the detector guess wrong.

## Relationships

Build these in Model view. All are one-to-many from the dimension to the fact, with single cross-filter direction.

| From | To | Cardinality |
| --- | --- | --- |
| `dim_customer[customer_key]` | `fact_sales[customer_key]` | one-to-many |
| `dim_product[product_key]` | `fact_sales[product_key]` | one-to-many |
| `dim_geography[geography_key]` | `fact_sales[geography_key]` | one-to-many |
| `dim_date[date_key]` | `fact_sales[order_date_key]` | one-to-many |
| `dim_date[date_key]` | `fact_sales[ship_date_key]` | one-to-many |

`dim_date` joins twice, on `order_date_key` and `ship_date_key`. Power BI allows only one active relationship between two tables, so make the order-date one active and leave the ship-date one inactive, reaching it with `USERELATIONSHIP` when a measure needs it. Mark `dim_date` as the date table using `full_date`, or the time intelligence functions below will not work.

## Measures

**Total Sales**

```dax
Total Sales = SUM ( fact_sales[sales] )
```

**Total Profit**

```dax
Total Profit = SUM ( fact_sales[profit] )
```

**Profit Margin %**

```dax
Profit Margin % = DIVIDE ( [Total Profit], [Total Sales] )
```

**Avg Discount**

```dax
Avg Discount = AVERAGE ( fact_sales[discount] )
```

**Loss-Making Lines %**

```dax
Loss-Making Lines % = DIVIDE ( CALCULATE ( COUNTROWS ( fact_sales ), fact_sales[is_loss_making] = TRUE ), COUNTROWS ( fact_sales ) )
```

**YoY Sales Growth %**

```dax
YoY Sales Growth % = VAR PriorYear =
    CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( dim_date[full_date] ) )
RETURN
    DIVIDE ( [Total Sales] - PriorYear, PriorYear )
```

Format `Profit Margin %`, `Avg Discount`, `Loss-Making Lines %`, and `YoY Sales Growth %` as percentages. They return ratios rather than pre-multiplied numbers, so formatting is what makes them read correctly.
